# 기념일·서프라이즈 시나리오 AI 에이전트 작업계획서

## 1. 프로젝트 개요

### 1.1 서비스명

**기념일·서프라이즈 시나리오 AI 에이전트**

### 1.2 목표

커플, 가족, 친구 등 동행 관계와 기념일 종류, 예산, 성향, 준비 가능 시간을 종합해 실행 가능한 이벤트 시나리오를 생성한다. 단순히 장소를 추천하는 서비스가 아니라, 선물·메시지·활동·전달 시점을 하나의 경험으로 구성하고 예산 및 조건을 검증하는 것을 목표로 한다.

### 1.3 핵심 가치

- 관계와 상황에 맞는 개인화된 이벤트 제안
- LLM이 필요한 Tool을 선택하여 날짜·비용·선물 후보를 정확히 확인
- RAG 문서를 근거로 과도하거나 부담스러운 이벤트를 피하는 설계

## 2. 사용자 시나리오

### 2.1 대표 요청

> "사귄 지 100일이에요. 상대는 내향적이고 과한 서프라이즈는 부담스러워해요. 예산은 8만 원이고, 퇴근 후 3시간 안에 할 수 있는 계획을 만들어 주세요."

### 2.2 성공 결과

에이전트는 다음을 포함한 계획을 반환한다.

1. 기념일과 관계·성향·예산·시간 조건 요약
2. 추천 이유와 참고한 가이드 요약
3. 시간 순서가 있는 이벤트 시나리오
4. 선물 또는 소품 후보와 예상 비용
5. 총비용·준비 시간·조건 충족 여부
6. 변경이 필요한 경우의 대안

### 2.3 예시 결과

```text
18:30  짧은 안부 메시지와 "오늘 저녁에 작은 선물이 있어"라는 안내
19:00  조용한 공간에서 손편지와 질문 카드 3장 전달
19:30  취향 기반 소품 선물 전달
20:00  함께 고를 수 있는 다음 데이트 위시리스트 작성

예상 비용: 질문 카드 12,000원 + 선물 45,000원 + 포장 5,000원 = 62,000원
검증 결과: 예산 80,000원 이내, 3시간 이내, 소규모 이벤트 조건 충족
```

## 3. 전체 아키텍처

```text
사용자 요청
  ↓
입력 분석 LLM
  ├─ 관계·기념일·성향·예산·시간 조건 추출
  ├─ 누락된 필수 조건 확인 질문 생성
  └─ 필요한 Tool 및 RAG 검색 판단
  ↓
RAG 검색 + Mock Tool 호출
  ↓
시나리오 생성 LLM
  ↓
예산·시간·선호 조건 검증
  ↓
최종 시나리오 응답
```

### 3.1 구성 요소별 책임

| 구성 요소 | 책임 |
| --- | --- |
| LLM | 요청 이해, 조건 추출, Tool 선택, 결과 종합, 자연어 시나리오 생성 |
| RAG | 기념일·성향·예산별 이벤트 가이드와 배려 원칙을 근거로 제공 |
| Tool | 날짜 계산, 선물 후보 조회, 예산 합산, 일정 조건 검증 |
| Mock 데이터 | 선물 후보와 예시 사용자 조건을 제공 |

## 4. LLM 설계

### 4.1 LLM 입력 항목

- 관계 유형: 연인, 가족, 친구, 배우자 등
- 기념일 종류 및 날짜: 100일, 생일, 첫 만남, 1주년 등
- 상대 성향: 내향형/외향형, 깜짝 이벤트 선호도
- 취향 및 금기: 취미, 좋아하는 선물 유형, 알레르기, 피해야 할 요소
- 제약 조건: 총예산, 준비 시간, 진행 가능 시간, 이벤트 규모

### 4.2 LLM의 처리 원칙

1. 모르는 금액·날짜·재고를 추측하지 않고 Tool을 호출한다.
2. 성향과 선호가 충돌하면 강한 서프라이즈보다 상대의 부담을 줄이는 방향을 우선한다.
3. 비용 또는 시간 제한을 넘으면 대안을 함께 제시한다.

### 4.3 권장 Structured Output

LLM의 중간 결과는 아래 필드를 갖는 구조화된 데이터로 만든다.

| 필드 | 설명 |
| --- | --- |
| `occasion` | 기념일 종류 |
| `constraints` | 예산, 시간, 성향, 금기 조건 |
| `required_tools` | 호출할 Tool 목록 |
| `rag_query` | RAG 검색 질의 |
| `scenario_steps` | 시간 순서 이벤트 단계 |
| `estimated_total` | 예상 총비용 |
| `validation_status` | 검증 통과/수정 필요 |
| `alternatives` | 조건 불충족 시 대안 |

## 5. Tool 설계

초기 버전은 외부 결제·예약을 실행하지 않는 Mock Tool로 구현한다.

| Tool | 입력 | 출력 | 목적 |
| --- | --- | --- | --- |
| `calculate_anniversary` | 관계 시작일, 기준일 | 경과 일수, 기념일 여부 | 100일·1주년 등 날짜 계산 |
| `search_gift_candidates` | 취향 태그, 예산, 제외 조건 | 선물 후보 목록 | 조건에 맞는 Mock 선물 조회 |
| `calculate_budget` | 선택 항목과 가격 | 항목별 금액, 총액, 초과 여부 | 예산 검증 |
| `validate_schedule` | 이벤트 단계, 시작 시각, 제한 시간 | 예상 소요 시간, 충돌 여부 | 실행 가능성 검증 |
| `create_scenario_draft` | 조건, RAG 근거, Tool 결과 | 시나리오 초안 | LLM 생성 결과를 구성 |

### 5.1 Tool 호출 예시

```text
LLM 판단: 100일 여부와 예산 검증이 필요함
  → calculate_anniversary(start_date, today)
  → search_gift_candidates(tags, budget, avoid_for)
  → calculate_budget(selected_items)
  → validate_schedule(scenario_steps, available_time)
```

## 6. RAG 설계

### 6.1 RAG 문서 범위

| 문서 분류 | 포함 내용 |
| --- | --- |
| 기념일 가이드 | 100일, 생일, 첫 만남, 1주년별 이벤트 아이디어와 주의점 |
| 성향별 가이드 | 내향형·외향형, 깜짝 이벤트 선호도별 적절한 이벤트 강도 |
| 관계 단계 가이드 | 썸, 연애 초반, 장기 연애, 가족, 친구 관계의 표현 방식 |
| 예산 가이드 | 3만 원·5만 원·10만 원대별 준비 항목과 비용 배분 사례 |
| 선물 가이드 | 취미·실용성·감정 표현 중심 선물 선택 기준과 금기 조건 |
| 메시지 가이드 | 편지, 카드, 초대 메시지 작성 원칙과 말투 예시 |
| 배려·안전 가이드 | 공개 이벤트, 강요, 과소비, 민감 주제에 대한 주의 원칙 |

### 6.2 문서 메타데이터

RAG 문서 청크에는 다음 메타데이터를 저장한다.

| 필드 | 예시 |
| --- | --- |
| `document_type` | `personality_guide`, `anniversary_guide` |
| `occasion` | `100days`, `birthday`, `anniversary` |
| `relationship_stage` | `early_relationship`, `long_term` |
| `personality` | `introvert`, `extrovert` |
| `budget_range` | `under_30000`, `30000_to_80000` |
| `surprise_level` | `low`, `medium`, `high` |
| `content` | 검색 대상 본문 |

### 6.3 검색 규칙

1. LLM이 추출한 기념일·관계 단계·성향·예산을 검색 질의와 필터로 사용한다.
2. 상위 관련 문서 3~5개만 시나리오 생성 LLM에 전달한다.
3. 조건에 맞는 문서가 없으면 일반적인 배려 가이드를 사용하고 불확실성을 표시한다.

## 8. 워크플로우 및 Agent 역할

### 8.1 권장 Agent 분리

| Agent | 책임 |
| --- | --- |
| Orchestrator Agent | 요청을 분석하고 RAG·Tool·하위 Agent 실행 순서를 결정 |
| Scenario Agent | RAG 근거와 조건으로 시간 순서 이벤트 시나리오 생성 |
| Budget & Schedule Validator Agent | 비용·시간·제약 조건 검증 및 대안 제안 |

### 8.2 상태 흐름

```text
receive_request
  → extract_constraints
  → retrieve_rag_context
  → call_tools
  → generate_scenario
  → validate_plan
  → return_result
```

## 9. 구현 순서

### 1단계: 기본 데이터와 Mock Tool

- `users`, `partner_profiles`, `gift_catalog` Mock 데이터를 준비한다.
- 기념일 계산, 선물 검색, 예산 계산, 일정 검증 Tool을 구현한다.
- 각 Tool의 입력·출력 JSON 형식을 고정하고 단위 테스트를 작성한다.

### 2단계: RAG 구축

- 기념일·성향·예산·안전 가이드 문서를 Markdown 또는 JSON으로 작성한다.
- 문서를 청크로 나누고 임베딩과 메타데이터를 저장한다.
- 조건별 검색 품질을 확인할 질의 세트를 준비한다.

### 3단계: LLM Agent 연결

- 요청에서 구조화된 조건을 추출하는 프롬프트와 스키마를 만든다.
- LLM이 RAG 검색과 Tool 호출 결과를 받아 시나리오를 생성하게 한다.
- Tool 결과로 예산·날짜·시간을 검증한 뒤 자연어 결과에 반영한다.

### 4단계: 통합 및 검증

- LLM, RAG, Mock Tool을 하나의 요청 흐름으로 연결한다.
- 대표 사용자 조건으로 결과 품질과 검증 결과를 확인한다.

## 10. 테스트 계획

| 시나리오 | 기대 결과 |
| --- | --- |
| 100일·내향형·8만 원 조건 | 저강도 이벤트, 예산 이내 시나리오 생성 |
| 예산 5만 원인데 선물 합계 7만 원 | 초과를 표시하고 저가 대안 제시 |
| 2시간 제한인데 계획이 3시간 | 시간 충돌 표시 및 단계 축소 제안 |
| 공개 이벤트 비선호 | 공개 고백·대형 이벤트를 추천하지 않음 |
| RAG 문서 미검색 | 일반 가이드로 답변하고 근거 부족을 표시 |

## 11. 범위와 제약

- 초기 버전은 실제 결제, 예약, 메시지 전송을 하지 않는다.
- 가격, 재고, 일정은 Mock 데이터 기준이며 실제 상업 정보가 아니다.
- AI는 관계를 평가하거나 감정을 단정하지 않고, 사용자가 제공한 조건만 활용한다.
- 추천 결과는 의사결정 보조이며, 실제 실행은 사용자가 직접 결정한다.
